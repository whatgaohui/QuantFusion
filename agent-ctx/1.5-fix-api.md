# Task 1.5-fix-api: Fix API Routes for New Prisma Schema

## Summary
Updated all 8 API route files to work with the new 19-model Prisma schema. The old routes referenced fields from the old schema that no longer exist.

## Changes Made

### 1. Created `/src/lib/auth-utils.ts`
- New utility module providing `DEFAULT_USER_ID` constant and `ensureDefaultUser()` function
- Uses `db.user.upsert()` to handle race conditions when creating the default user
- Required because all models now have a `userId` foreign key to the User table

### 2. Fixed `/src/app/api/portfolio/positions/route.ts`
- `status: 'ACTIVE'` → `status: 'open'` / `status: 'closed'`
- `createdAt` → `openedAt` for ordering
- POST: `name`/`buyPrice`/`buyDate`/`cycleDays`/`stopLossPct`/`takeProfitPct` → `market`/`side`/`avgCost`/`quantity`/`stopLoss`/`takeProfit`/`notes`
- DELETE: `sellPrice`/`sellDate`/`sellReason` → `currentPrice`/`realizedPnl`/`closedAt`
- TradeLog: `action: 'BUY'/'SELL'` → `side: 'buy'/'sell'`, removed `name`/`reason`/`profitPct`, added `userId`/`market`/`totalAmount`/`commission`/`tradeTime`/`source`
- Added `include: { lots: true }` for GET

### 3. Fixed `/src/app/api/portfolio/summary/route.ts`
- `status: 'ACTIVE'` → `status: 'open'`
- `position.buyPrice` → `position.avgCost`
- `position.name` → removed (not in schema)
- Added `market`/`side` to position summaries
- Added DB update of `currentPrice`/`unrealizedPnl` when fetching live quotes

### 4. Fixed `/src/app/api/portfolio/check/route.ts`
- `status: 'ACTIVE'` → `status: 'open'`
- `position.buyPrice` → `position.avgCost`
- `position.buyDate` → `position.openedAt`
- `position.takeProfitPct`/`position.stopLossPct` (percentages) → `position.takeProfit`/`position.stopLoss` (absolute price values)
- Removed `cycleDays`/`EXPIRED` check (field no longer exists)
- `status: 'CLOSED'` → `status: 'closed'`
- `sellPrice`/`sellDate`/`sellReason` → `currentPrice`/`realizedPnl`/`closedAt`

### 5. Fixed `/src/app/api/trades/route.ts`
- `orderBy: { createdAt: 'desc' }` → `orderBy: { tradeTime: 'desc' }`
- Added `userId` filter

### 6. Fixed `/src/app/api/watchlist/route.ts`
- `addedAt` → `createdAt` for ordering, then changed to `sortOrder: 'asc'`
- `findUnique({ where: { symbol } })` → `findUnique({ where: { userId_symbol: { userId, symbol } } })` (composite unique key)
- Added `userId`, `market`, `groupName`, `sortOrder` fields to create
- Added `id`-based delete option alongside symbol-based delete

### 7. Fixed `/src/app/api/alerts/route.ts`
- `condition: 'ABOVE'/'BELOW'` → `alertType: 'price_above'/'price_below'/'volume'/'rsi'/'macd'/'custom'`
- `targetPrice` → `targetValue`
- `status: 'ACTIVE'/'TRIGGERED'/'EXPIRED'` → `isActive: true/false` + `isTriggered: true/false` + `triggeredAt`
- PATCH: changed from status-based to isActive/isTriggered/currentValue fields
- Added `notifyChannels` field

### 8. Fixed `/src/app/api/signals/scan/route.ts`
- Removed all `db.signalResult` references (model no longer exists)
- Removed `db` import entirely (no database operations needed)
- Results are now returned directly without saving to DB
- Removed `name` parameter from `analyzeSignals()`
- Added `scannedAt` field to results
- GET without symbol now returns 400 instead of querying non-existent SignalResult

### 9. `/src/app/api/ai/sentiment/route.ts` - No changes needed
- Does not use any database models, only uses ZAI SDK and Finnhub API

## Verification
- `bun run lint` passes with no errors
- All API endpoints return 200 status codes
- Position creation with new schema fields works correctly
- Trade log creation with new schema fields works correctly
- Watchlist and alerts queries work with new schema fields
- Default user is auto-created via upsert to satisfy foreign key constraints
